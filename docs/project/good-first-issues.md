# Suggested good first issues

Create these as GitHub issues with labels `good first issue` and `help wanted` (plus area labels). Do **not** label architecture refactors as first issues.

1. **Docs:** Expand one FAQ answer with a worked CLI example (`documentation`).
2. **Docs:** Add alt text / caption review for one diagram (`documentation`, `accessibility`).
3. **Curation:** Curate one scaffold toward L2 following the disease-curation playbook (`disease-curation`) — pick a module that already has partial KG JSON.
4. **Sources:** Add missing license URL to one `data/sources/registry.yaml` entry (`data-source`).
5. **API:** Add a documented curl example for `/api/health` and compare to OpenAPI (`api`, `documentation`).
6. **Testing:** Add a fixture-backed evidence record for an existing adapter test (`testing`).
7. **Frontend:** Keyboard-focus visible state on one dashboard control (`frontend`, `accessibility`).
8. **Research:** Write a second disease comparison example (`sle` vs `ad`) as a markdown research page (`research`, `documentation`).

Maintainer: apply labels `good first issue`, `help wanted`, `documentation`, `disease-curation`, `data-source`, `research`, `frontend`, `api`, `testing` as needed.
