# v0.2.1 stabilization design

## Objective

Stabilize the v0.2.0 milestone before starting the next roadmap milestone. Ship the work as one backward-compatible v0.2.1 patch release whose scope is limited to verified defects, owned deprecations, recently introduced typing gaps, release hygiene, and a current technical-debt ledger.

The release must improve correctness and maintainability without changing Compare V2 biomedical semantics, adding product features, widening the public API, or starting the next milestone early.

## Release shape

Use one v0.2.1 release with small, reviewable change sets rather than several micro-releases. The fixes touch related quality gates and public version surfaces, so a single patch provides a clearer compatibility statement and avoids repeated release-metadata churn.

No tag, push, pull request, merge, package publication, or hosted release is part of this implementation unless separately authorized. Local commits may keep the work auditable.

## Runtime correctness and compatibility

Replace project-owned uses of deprecated naive UTC construction in the asynchronous job queue, hypothesis agent, and dossier web flow with timezone-aware UTC values. Machine-facing serialized timestamps must carry an explicit UTC offset. Existing filename-safe timestamp tokens retain their current `YYYYMMDDTHHMMSSZ` shape so archive and download naming remains compatible.

Correct the typing defects found in newly shipped biomedical surfaces:

- Give Compare V2's grouped-entity accumulator an explicit stable type.
- Validate persisted Compare V2 status values at the storage boundary before constructing the typed response. The two supported states remain `comparable` and `insufficient_data`; an unknown stored state is treated as invalid persisted data rather than silently reinterpreted.
- Type Open Targets snapshot identifiers as UUID values and normalize optional phase data without calling `int()` on `None` or an unsupported value.
- Remove obsolete dossier type-suppression comments after confirming the imports are typed correctly.

Invalid external Open Targets phase values must not crash ingestion. Missing or non-integer phase values normalize to no phase, matching the adapter's optional field contract. Invalid stored Compare payloads must follow the service's existing persistence-error path and must not be presented as valid results.

## Quality-gate ratchet

Extend the existing informational mypy target only to the recently shipped surfaces covered by this stabilization work: Open Targets import adaptation, Compare V2, and dossier service/API modules. Do not attempt a repository-wide strict typing conversion in this patch.

Fix warnings owned by the project when they indicate deprecated runtime behavior. Keep third-party FastAPI/TestClient `httpx2` and SHAP/Matplotlib warnings visible and document them in the debt ledger; dependency-family migrations require separate compatibility work and are not patch-release drive-by upgrades.

The pytest cache and temporary-directory permission warnings observed in the managed Windows sandbox are environment artifacts, not product defects. Verification uses a workspace-local base temporary directory and does not weaken or filter warning reporting.

## Technical-debt ledger

Refresh `TECHNICAL_DEBT_ISSUES.md` so it distinguishes completed historical audit items from active work. Preserve useful history, but place a concise current backlog first with ownership rationale, impact, evidence, acceptance criteria, and a recommended release target.

Immediate priorities are:

1. Complete the incremental mypy ratchet across remaining untyped runtime boundaries.
2. Plan and test the FastAPI/Starlette TestClient migration to `httpx2` before the compatibility window closes.
3. Isolate or replace SHAP/Matplotlib deprecated color-map usage through a tested dependency upgrade.
4. Standardize all remaining timestamp creation and serialization behind one UTC utility.
5. Add a reproducible SPDX/SBOM license report to the release gates.
6. Add a trusted PyPI publication workflow with provenance and a dry-run package validation path.
7. Reduce validation cost and ambiguity in the generated disease scaffold while retaining strict gates for the curated disease set.

Items may be reordered only if implementation evidence changes their risk. Deferred items must not be described as fixed by v0.2.1.

## Test strategy

Use test-driven regression work for behavior changes:

- UTC tests prove serialized machine timestamps are explicitly UTC while filename tokens remain compatible.
- Compare service tests prove supported stored states round-trip and unsupported states fail through the existing persistence boundary.
- Open Targets adapter tests cover integer, numeric-string, missing, and invalid phase values.
- A focused mypy invocation first demonstrates the current failures, then passes after the typing fixes and Makefile ratchet.

After focused tests pass, run the repository gates with the project virtual environment: Ruff lint and formatting, lock verification, import-boundary checks, public metadata and font checks, the complete offline suite, the integration tier when local Redis support is available, strict documentation build, package-content checks, and curated disease validation. Run the Playwright browser test when Chromium is available. Record any unavailable environmental gate explicitly rather than claiming it passed.

Warnings are reviewed after the full suite. The acceptance bar is no project-owned UTC deprecation warnings in the exercised paths; known third-party warnings remain documented and unhidden.

## Release metadata and documentation

Update all canonical current-version surfaces from v0.2.0 to v0.2.1, including package/runtime metadata, citation and CodeMeta files, generated public status, roadmap/status text, changelog, and dedicated release notes as required by the repository's metadata checker. Preserve historical v0.2.0 records, its tag, archive metadata, and release notes unchanged.

The changelog and v0.2.1 notes must state that this is a backward-compatible stabilization patch, enumerate user-visible correctness changes, list verification performed, and disclose remaining dependency warnings and technical debt. Do not invent an archive DOI or imply publication that has not occurred.

## Failure handling

Each fix stops at a failing focused test or quality gate until its root cause is understood. Do not suppress warnings, loosen assertions, broaden exception handling, or remove a type-checked file to make a gate green.

If a proposed fix requires a public contract break, dependency-family migration, data rewrite, or architecture change, defer it to the technical-debt ledger with a release target instead of expanding v0.2.1. If final verification finds a regression that cannot be fixed within these boundaries, v0.2.1 remains incomplete and the next milestone does not begin.

## Completion criteria

The stabilization is ready for release handoff when:

- All scoped regression tests and local quality gates pass with fresh evidence.
- Recently shipped scoped modules pass the expanded mypy ratchet.
- No exercised project code emits the deprecated naive-UTC warnings addressed here.
- Public metadata consistently reports v0.2.1 and historical release records remain intact.
- The current technical-debt list is prioritized, testable, and explicit about what remains open.
- The working diff contains no unrelated refactors or generated debris.
